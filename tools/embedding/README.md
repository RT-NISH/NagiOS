# tools/embedding — M24 embedding model pipeline

Reproducible, credential-free pipeline for the Nagi M24 embedding provider
(`crates/nagi-embedding-provider`).

| Step | Command | Output |
| --- | --- | --- |
| Fetch pinned upstream files (immutable revision, size + SHA-256 checked) | `tools/embedding/fetch.sh [--with-reference]` | `${NAGI_EMBEDDING_CACHE:-~/.cache/nagi-embedding}/<revision>/` |
| Convert (stdlib-only, deterministic) | `python3 tools/embedding/convert_e5.py --input <dir> --output multilingual-e5-small.nemb` | `.nemb` whose SHA-256 must equal `manifest.toml` `[converted].sha256` |
| Verify every pin agrees (stdlib-only) | `python3 tools/embedding/verify_pins.py --artifact <nemb> [--input <dir>] [--models-lock-proposal <md>]` | one PASS/FAIL line per check; non-zero exit on any mismatch |
| Regenerate reference data (verification only) | `tools/embedding/regenerate_reference.sh [--write]` | fresh hash-pinned venv; rebuilds `tests/m24-embedding/{parity_reference,tokenizer_parity}.json` and compares byte-for-byte |
| Full host acceptance | `tests/m24-embedding/run.sh` | log under `$NAGI_EMBEDDING_CACHE/evidence/` |

Pins (see `manifest.toml`): `intfloat/multilingual-e5-small` at
`614241f622f53c4eeff9890bdc4f31cfecc418b3`, MIT. The ONNX export is used only
as an independent reference and is never converted or shipped. The provenance
chain from the original weights/tokenizer/config to the converted `.nemb`, the
Rust pin and the `EmbeddingSpaceId` is tabulated in
`.dev/workstreams/hark-m24-embedding/integration-proposal.md` §3.1.

## Reference regeneration (Python, verification only)

The converter and `verify_pins.py` use only the Python standard library. The
two reference generators need third-party packages; they are pinned by exact
version **and** SHA-256 for the complete transitive closure:

- `requirements-reference.in` — the resolved set (CPython 3.12.15).
- `requirements-reference.txt` — generated by
  `python3 pin_requirements.py requirements-reference.in requirements-reference.txt`
  from the PyPI JSON API; wheels only (no sdists, so nothing is built) for
  Linux x86_64/aarch64, macOS and Windows amd64.

Procedure (what `regenerate_reference.sh` does):

1. `fetch.sh --with-reference` (adds `onnx/model.onnx`, SHA-256 checked).
2. `python3.12 -m venv <work>/venv`, then
   `pip install --require-hashes --only-binary :all: -r requirements-reference.txt`
   and `pip check`; the installed set is logged with `pip freeze --all`.
3. `reference_e5.py` over `tests/m24-embedding/parity_corpus.json` and
   `tokenizer_parity.py` over the localization catalogs + seeded random strings.
4. Compare both outputs byte-for-byte with the committed copies; exit non-zero
   on any difference (`--write` replaces the committed copies instead).

The venv's bundled `pip` (25.0.1 with CPython 3.12.15) is not itself
hash-pinned. A recorded run is in
`tests/m24-embedding/logs/reference-regeneration-20261009T004802Z.txt`
(both files byte-identical).
