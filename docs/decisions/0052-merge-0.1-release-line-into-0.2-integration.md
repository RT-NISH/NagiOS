# 0052: Merge the 0.1 release line into the 0.2 integration line

- Status: Accepted
- Date: 2026-10-05
- Decided by: repository owner (delegated merge; recorded by the integrating agent)

## Context

`main` (the Nagi 0.1 release line, M17–M30 completion sweep) and
`codex/integration-next-phase` (the Nagi 0.2 workstream integration line)
diverged at `1993a45` on 2026-09-26. By 2026-10-05 `main` held 253 commits and
the integration line 134 that the other side lacked. A merge produced 31
conflicting paths. Several conflicts came from the same problem being solved
independently on both lines, not from incompatible goals.

## Decisions

1. **`nagi-model-manager` follows `main`.** The integration line carried only
   the first foundation commit (plus a CRLF test tweak that `main` fixed
   separately in `fc8994c`). `main` holds the complete runtime foundation and
   the M20/M26 guest Model Store work built on it. The model-runtime contract,
   manifest schema, and workstream doc follow `main` for the same reason.
2. **`nagi-posix` follows `main`.** Both lines fixed M17 over-aligned
   allocation and pthread creation diagnostics. `main`'s implementation is
   later, more complete (bounded thread scheduler, script-thread stacks,
   guest urandom), and is the one that reached M17 PASS on target CI. The
   integration line's `thread_diagnostics.rs`, unreferenced after the merge,
   is removed.
3. **The host i18n foundation is renamed `nagi-i18n`.** Both lines added a
   package named `nagi-localization`: the integration line's host-side
   foundation in `crates/` (serde catalogs, formatting, pseudo-locale) and
   `main`'s `no_std` guest catalog in `user/` that the shipped M29 Desktop and
   Albert depend on. One workspace cannot hold two packages with one name.
   The guest crate keeps its name because shipped code and acceptance depend
   on it; the host foundation, which had no in-tree dependents, moves to
   `crates/nagi-i18n`. Converging the guest UI onto the shared foundation is
   follow-up work for the localization workstream.
4. **Desktop colors use the design-system tokens.** The integration line moved
   the M10 Desktop palette onto `nagi-ui` tokens; `main` added a Settings
   overlay with its own literal colors. The merged Desktop uses tokens for
   both, mapping the focus indicator to `ColorRole::Focus`, the top bar to
   `SurfaceSunken`, and Settings options to `SurfaceRaised`.
5. **Developer tooling keeps both sides.** `nagi` keeps the pinned-toolchain
   lookup and falls back to the cargo shim beside `rustup`; `nagi-pkg` keeps
   both `manifest validate` and `build-signed`; the CLI keeps the 0.2
   `diagnostics`/`verify`/`smoke`/`dev`/`test --acceptance` commands and the
   0.1 `m18`–`m30` milestone commands. CI runs the integration line's M17
   acceptance runner and then `main`'s M18–M30 target acceptance steps.
6. **Status history keeps both lines.** `docs/implementation_status.md` takes
   `main`'s current-status header and keeps the integration line's checkpoints
   in a separate, clearly historical section.

## Consequences

- `crates/nagi-search-core` still pins `nagi-search`/`nagi-model` by git
  revision; it can now switch to path dependencies (follow-up).
- ADR numbers 0011–0014 exist twice (one per line). They are distinct files
  and are not renumbered, so existing references stay valid.
