# DEC-003 — Memoryの機密分類と所有範囲

**状態:** CONFIRMED  
**最終合意:** 2026-10-25までのNagi_chat議論  
**対象:** 0.3、0.4+  
**関連:** DEC-002、DEC-004、DEC-005

## 決定事項

- **自動分類＋ユーザー修正（選択C）:** NagiはMemoryを通常／個人・非公開／機密などに自動分類し、ユーザーは表示・修正できる。
- **優先順位:** ユーザーが明示的に設定した保護指定と、元データの機密分類はAIの推定より優先する。元データの機密指定をAIが単独で解除しない。
- **不確実なら共有を保留:** 分類が不明・競合・信頼不足ならクラウドへの自動送信をしない。
- **由来を継承:** 機密資料から派生したMemoryや要約も、機密指定を引き継ぐ。一般化・要約だけで機密解除できない。
- **可視化:** Memoryの内容、分類、根拠、最終利用、外部共有履歴を確認・訂正・削除できるようにする。
- **所有範囲を分離:** User / Profile、Task、Agent、Team、Organization Memoryを暗黙に混合しない。個人の記憶を自動的にTeam・Organization共有へ昇格しない。
- **権限は独立:** 記憶する権限とMemoryを検索する権限、他Agentへ渡す権限、Cloudへ送信する権限を分離する。

## 未確定事項

分類の厳密なSchemaとUI、分類に失敗した場合の診断、同一Memoryの複数元資料と分類衝突、チーム管理者による分類変更の境界。

## Roadmapとの関係

0.2のIdentity・Permissions・Settings・provenanceが基礎。0.3はMemory StoreとPermission-filtered Unified Contextを作る。0.4+の子AgentにはTask単位で許可されたMemoryだけを渡す。
