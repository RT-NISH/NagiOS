# DEC-001 — AIの自律性とAction実行

**状態:** CONFIRMED  
**最終合意:** 2026-10-25までのNagi_chat議論  
**対象:** 0.3 Personal Agent、0.4+への継承  
**関連:** DEC-002、DEC-005、DEC-007

## 決定事項

1. **承認済みTask内での自律性:** ユーザーが明確に指定した目的・対象・権限範囲の内側では、Nagiは可逆な下位作業を毎回確認せずに実行できる。必要なPublic ActionとProvider側の権限確認は省略しない。
2. **権限と習慣の分離:** 繰り返された行動やPreferencesから操作方法を学んでも、読み取り・変更・共有・送信の許可範囲が拡大することはない。
3. **メール送信:** 「送信して」という明示の依頼、送信先、内容、対象範囲、送信権限が確定している場合は、毎回の重複確認なしで送信してよい。宛先・CC/BCC・添付・共有先を推測で拡張しない。
4. **機密情報の外部送信:** 機密という理由だけで無条件に再承認を要求しない。ただし、送信先・範囲の明示的な許可、元データの扱い、組織Policyのすべてが送信を認めている必要がある。読める権限は送信する権限を意味しない。
5. **認証情報:** パスワード、秘密鍵、API keyなどは一般的な外部送信や通常のMemory利用と別の厳しい境界で取り扱う。
6. **取消とActivity:** Nagiが何をしたか、どこまで完了したかを追跡し、可能な範囲でPause / Cancel / Undoできるようにする。送信済みメールやRemote変更を「Undo可能」と偽らない。

## 実行上の優先順位

OSの現在のPermission / Policy > ユーザーの明示的な指示・禁止 > 限定された承認済みTask > 学習した嗜好・習慣。Policyに反するユーザー指示は実行しない。Action実行時に現行Scopeを評価する。

## まだ決めていないこと

- Action種別ごとのリスク分類、事前承認のUI、確認を再要求する重大変更の閾値。
- Task実行の具体的な時間・Retry・Resource上限。
- 可逆Action / 結果不明な外部Actionの厳密な形式とテスト。

## Roadmapとの関係

0.2では型付きPublic Action、Identity、Permission、Activity、Wayback等の土台を整える。0.3で単一Nagiが複数アプリを順次操作する。0.4+の専門Agentは親から**権限を狭める委譲**しか受けられず、独自の権限発行はしない。
